# GroqCloud AI Integration

The AI screens are wired to **GroqCloud (`llama-3.1-8b-instant`)**, grounded in each
tender's own PDF documents from eTenders.

---

## 1. Setup

Get a free key at **https://console.groq.com/keys**, then:

```bash
# .env.local
GROQ_API_KEY=your-key
GROQ_MODEL=llama-3.1-8b-instant
```

Never prefix it with `NEXT_PUBLIC_`. `src/lib/groq.server.ts` imports
`server-only`, so importing it from a client component is a **build error**.
imported a type from the server module and pulled the key toward the bundle.
The client-safe types now live in `src/types/ai.ts`.

Note on key formats: newer AI Studio keys start with `AQ.` rather than `AIza`.
Both work, but they are **not** OAuth tokens — they go in the `x-goog-api-key`
header. Sending one as `Authorization: Bearer` returns 401.

## 2. ⚠️ The free tier is far smaller than the docs suggest

Google's published figures say 250–1,500 requests/day for Flash. The actual
quota on this project, read from the 429 response:

```
quotaId:    GenerateRequestsPerDayPerProjectPerModel-FreeTier
quotaValue: 20
```

**20 requests per day.** That is the binding constraint on the whole feature,
and it drove three design decisions:

1. **Persistent disk cache** (`src/lib/ai-cache.ts`). A summary is generated
   once per tender and reused for 7 days. Without it, ten page refreshes would
   burn half a day's budget. Next's `revalidate` alone is insufficient — it is
   in-memory and lost on restart.
2. **Failed results are never cached**, so a transient outage isn't frozen in
   for a week.
3. **Only one document per tender** is summarised, and `thinkingBudget: 0`
   is set to halve latency and token spend.

Quota resets at **midnight Pacific**. For real use, either enable billing or
move to `gemini-2.5-flash-lite`, which has a larger allowance.

## 3. Text extraction, not native PDF upload

Gemini can read PDFs natively, and it works — verified against a real 103-page
Newcastle Municipality security tender, correctly extracting the PSIRA
requirement, the 90/10 preference formula, the R300 document fee and the
compulsory briefing date.

But on the free tier, **document requests returned 503 far more often than
they succeeded**, while plain text requests went through immediately. So the
primary path is now:

```
eTenders PDF → pdf-parse (per-page text) → page-tagged prompt → Gemini
```

This is faster, uses fewer tokens, and keeps **real page numbers** for
citations. Native PDF upload is retained only as a fallback for scanned,
image-only PDFs that have no text layer, where Gemini's OCR is needed.

Long documents are truncated to a 120k-character budget — the decision-relevant
content (advert, conditions of bid, evaluation criteria) sits at the front.

## 4. What the AI does, and does not, do

### Summaries — `/tenders/{id}/summary`

Grounded strictly in the document. The system prompt forbids inference and
requires a page number per claim. Citation markers are then mapped so that
each distinct page becomes one numbered source; two facts from the same page
share a marker, and a claim with no page gets **no** citation rather than a
fabricated one. There are unit tests asserting no citation ever dangles.

### Match score — `/tenders/{id}/match`

**The score is not generated by the model.** It is a fixed, weighted rubric:

| Factor | Weight |
|---|---|
| Category matches your profile | 35% |
| Province matches your profile | 25% |
| Time available to prepare | 25% |
| Documents published | 15% |

Match scores drive real bid/no-bid decisions, so they must be reproducible and
auditable. A language model emitting "87%" is neither. Gemini is used only for
the **"Before you bid"** warnings — extracting mandatory requirements
(CIDB grading, PSIRA, tax clearance, CSD registration, sureties) that a bidder
could be disqualified for missing.

### Deliberately absent

No bid/no-bid advice, no win-probability estimate, no pricing suggestion, and
no estimated contract value — the eTenders feed has no value field, so any
figure would be invented.

## 5. Degradation

Every failure path produces something honest rather than an error screen:

| Condition | Behaviour |
|---|---|
| No `GEMINI_API_KEY` | Sample summary, labelled as such |
| Daily quota exhausted | Metadata-only summary + "quota used up (resets midnight Pacific)" |
| Per-minute rate limit | Retried with exponential backoff + jitter |
| 503 overloaded | Retried up to 4 times, then metadata summary |
| PDF unreachable / not a PDF | Metadata summary + explanation |
| No documents published | Metadata summary; the Summarise CTA is hidden |

The daily cap is distinguished from per-minute limiting by inspecting
`quotaId` for `PerDay` — retrying a daily cap is pointless, and this is unit
tested against the real 429 payload.

A degraded summary restates only known listing metadata, is visibly flagged in
amber, shows "Generated from listing metadata", and carries no citations.
Nothing is inferred.

## 6. Verifying

```bash
npm test        # 21 tests, incl. citation mapping + quota classification
npm run dev
```

Then open `/tenders/877/summary` — a real Newcastle Municipality security
tender with a 103-page PDF.

Check remaining quota directly:

```bash
curl -s -H "x-goog-api-key: $GEMINI_API_KEY" \
  -H 'Content-Type: application/json' -X POST \
  "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent" \
  -d '{"contents":[{"parts":[{"text":"hi"}]}]}' | jq '.error.details'
```

Clear the cache to force regeneration (spends quota):

```bash
rm -rf .ai-cache
```

## 7. Production notes

- Move the cache from disk to Supabase or Redis — the disk cache does not
  survive a container rebuild, and serverless instances don't share it.
- Enable billing, or use Flash-Lite, before real users touch this.
- Summarise on **ingest** rather than on view: with 955 tenders and a shared
  cache, a nightly batch is far cheaper than on-demand generation.
- Google may train on free-tier data. Tender documents are public, so this is
  acceptable here — it would not be for user-uploaded bid documents.
- The free tier cannot be used to serve EU/EEA/UK/Swiss users.
